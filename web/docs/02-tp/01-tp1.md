# Travail 1 - Idée d'application 💡
 
:::note Général

<Row>

<Column>

## Objectif

Planifier votre application mobile avant de commencer à coder.
Ce TP est un **document remis en markdown** (texte, captures d'écran de wireframes ou photos de dessins à la main).

## Utilisation de l'IA

Dans ce TP, l'utilisation est possible dans les cas suivants:

- correction du langage / français. "Corrige les fautes de français / orthographe dans le fichier tp1.md"
- suggérer / corriger des conditions de satisfactions "Vérifie mes conditions de satisfaction pour RU 8"

</Column>

<Column>

## Remise

- Le texte doit se trouver dans le fichier `README.md` fournit avec le repo (à la racine).
- Les images doivent se trouver dans un répertoire nommées `images`, à la racine du repo. 

### Date

La journée de la séance 2.1, jusqu'à 23h59. Le dernier commit avant la remise sera corrigé, à moins que l'étudiant ne demande une pénalitée. La pénalité est de 10% sur la note obtenue, par jour de retard.


</Column>

</Row>

## Description de l'application

&#8203;<Highlight color="tip">2 points</Highlight> Décrivez votre application en quelques paragraphes.

- Quel est le but de l'application ?
- À qui s'adresse-t-elle ?
- Quelles sont les fonctionnalités principales ?

</Column>

<Column>

## Fonctionnalité avancée

&#8203;<Highlight color="tip">1 point</Highlight> Vous devez choisir et décrire une fonctionnalité avancée que vous devrez implanter d'ici la fin de la session, parmi les choix suivants:
- implantation de notifications mobiles : l'utilisateur peut recevoir des notifications même quand l'application n'est pas lancée
- déploiement sur le PlayStore : l'application est téléchargeable et fonctionnelle sur le PlayStore Android (attention nécessite de payer)
- support multi-plateforme : l'application fonctionne sur Android mais aussi en web et sur Windows
- API externe : l'application utilise une API externe REST pour l'essentiel des données (ex. utiliser l'API de Spotify pour une application de listes de lecture)
- utilisation de l'IA : l'application utilise des fonctionnalités d'IA comme la génération de messages ou d'images
- autre : validez avec votre enseignant si vous avez une autre idée, par contre il faut comprendre que le soutien technique n'est pas garanti (votre enseignant ne sait pas tout faire)

</Column>

## Dessins en wireframe

&#8203;<Highlight color="tip">3 points</Highlight> Dessinez les écrans principaux de l'application (à la main ou avec un outil comme Figma, Excalidraw, etc.).

- Minimum **4 écrans** différents (connexion, accueil, détail d'un truc, création d'un truc, etc.)
- La navigation entre les écrans doit être clairement indiquée (flèches, liens, annotations, etc.)
- Chaque écran doit indiquer des données éventuelles, prenez une feuille complète pour dessiner un écran et avoir de la place.


</Column>

<Column>

## Récits utilisateurs

&#8203;<Highlight color="tip">3 points</Highlight> Rédigez au moins **10 user stories** sous la forme :

> En tant que [rôle], je veux [fonctionnalité] afin de [bénéfice].

- Les récits doivent couvrir les fonctionnalités décrites et les écrans dessinés.
- Vous devez obligatoirement avoir un RU qui permet la création d'un compte / profil avec une image attachée que l'utilisateur peut choisir depuis la galerie du téléphone.
- Les règles de contrôle d'accès (qui peut faire quoi) doivent être clairement indiquées dans les récits.
- Si un récit fait partie du produit minimal viable (MVP), indiquez-le clairement.


</Column>

## Qualité du document / français

- Fautes d'orthographe ou de grammaire importantes 
- Document désorganisé ou difficile à lire 

# Annexe : exemple de l'application des profs


# Montpetit Ami

Montpetit Ami est une application qui aide une personne à entretenir ses relations en centralisant les informations sur ses amis, les rappels importants, les notes de suivi et des suggestions intelligentes pour reprendre contact au bon moment.

## Description

L'objectif de l'application est de réduire l'oubli et de faciliter le maintien des liens sociaux. L'utilisateur peut gérer ses contacts importants, consigner des nouvelles après une rencontre ou un échange, visualiser ce qui s'en vient pour chaque ami et recevoir de l'aide intelligente pour résumer l'information utile et préparer un message à envoyer.

## Élément avancé

**Catégorie choisie : IA**

La fonctionnalité avancée principale est l'utilisation de **Gemini via l'écosystème Firebase** pour analyser les notes associées à un ami et générer :

1. un court résumé contextualisé de ce qui est important à retenir à son sujet;
2. une proposition de message personnalisé que l'utilisateur peut ensuite partager avec le menu de partage du téléphone.

Cette composante ajoute une valeur concrète à l'application en transformant des notes brutes en information exploitable rapidement, ce qui aide l'utilisateur à reprendre contact de façon plus naturelle et pertinente.

## Stack technologique

| Composante | Technologie | Rôle |
| --- | --- | --- |
| Application cliente | Flutter / Dart | Développement d'une application unique pour Android et iOS |
| Authentification | Firebase Authentication | Connexion par courriel/mot de passe et par numéro de téléphone |
| Données applicatives | Firebase (écosystème) / base de données cloud | Stockage des profils d'amis, notes, rappels et liens entre utilisateurs |
| Intelligence artificielle | Gemini via Firebase | Résumé automatique et génération de message |
| Partage natif | Menu de partage du téléphone | Envoi rapide d'un message généré vers une autre application |
| Saisie vocale | Reconnaissance vocale mobile | Dictée des notes ajoutées à un ami |

## Récits utilisateur

Les récits utilisateur ci-dessous sont triés avec le **MVP en premier**, puis en ordre de priorité de réalisation pour **deux sprints**.

### RU-01 : Création de compte (OBLIGATOIRE)
**Sprint** : 1 **MVP** : Oui **Points** : 5

**Description** : En tant qu'utilisateur, je veux me créer un compte avec un nom d'utilisateur et un mot de passe afin de commencer à utiliser l'application et sauvegarder mes informations.

**Conditions de satisfaction** :
1. Le système valide la complexité minimale du mot de passe pour prévenir la création de comptes vulnérables.
2. Je peux attacher une photo de profil (OBLIGATOIRE) de la galerie du téléphone à mon profil.
3. Deux utilisateurs ne peuvent pas posséder le même nom d'utilisateur ou courriel.

### RU-02 : Connexion sécurisée
**Sprint** : 1 **MVP** : Oui **Points** : 5

**Description** : En tant qu'utilisateur, je veux me connecter avec un identifiant/mot de passe ou un numéro de téléphone via Firebase Authentication afin d'accéder à mon espace personnel de façon sécuritaire.

**Conditions de satisfaction** :
1. L'accès aux fonctionnalités et données de l'application est formellement bloqué tant que l'authentification n'est pas complétée avec succès.
2. Le processus d'authentification utilise un protocole sécurisé (Firebase) sans exposer d'identifiants en clair dans les logs ou en mémoire de façon persistante.

### RU-03 : Création d'une fiche ami
**Sprint** : 1 **MVP** : Oui **Points** : 8

**Description** : En tant qu'utilisateur, je veux créer une fiche ami avec son nom, sa date de naissance, la date de la dernière rencontre, la date du dernier contact et un niveau de proximité afin de suivre ma relation avec cette personne.

**Conditions de satisfaction** :
1. Seul l'utilisateur propriétaire de la fiche a les droits d'affichage (lecture), de modification et de suppression sur celle-ci.
2. L'accès direct aux fiches par le biais de requêtes réseau ou d'identifiants d'autres comptes est bloqué par des règles de sécurité (Firestore Security Rules).
3. Le nom de l'ami est obligatoire, la date de naissance est optionnelle.

### RU-04 : Ajout d'une note à un ami
**Sprint** : 1 **MVP** : Oui **Points** : 5

**Description** : En tant qu'utilisateur, je veux ajouter une note ou une publication à la fiche d'un ami après l'avoir vu ou après avoir reçu de ses nouvelles afin de conserver un historique de mes interactions.

**Conditions de satisfaction** :
1. Une note ne peut être ajoutée qu'à une fiche ami valide dont l'utilisateur connecté est le propriétaire exclusif.
3. La note est non vide et inférieure à 2000 caractères.

### RU-05 : Tableau de bord (Résumé de l'accueil)
**Sprint** : 1 **MVP** : Oui **Points** : 8

**Description** : En tant qu'utilisateur, je veux voir à l'arrivée sur l'application un résumé de ce qui s'en vient pour mes amis, comme un anniversaire ou un élément important mentionné dans mes notes, afin de savoir rapidement sur qui agir en priorité. 

**Conditions de satisfaction** :
1. Le tableau de bord extrait et affiche uniquement les événements associés aux amis créés par l'utilisateur connecté.
2. Aucune fuite d'informations (anniversaires, notes privées d'autrui) ne doit être possible via l'affichage global ou la mise en cache.

### RU-06 : Déconnexion sécurisée
**Sprint** : 1 **MVP** : Oui **Points** : 2

**Description** : En tant qu'utilisateur, je veux me déconnecter afin de protéger l'accès à mon compte lorsque j'ai terminé.

**Conditions de satisfaction** :
1. La déconnexion invalide immédiatement le jeton de session (session token) auprès de Firebase, bloquant tout accès subséquent.
2. Toutes les données locales sensibles de l'utilisateur stockées en cache ou en état applicatif sont purgées de l'appareil.
3. L'application redirige l'utilisateur vers l'écran d'authentification et lui refuse le retour arrière vers l'application sans reconnexion.

### RU-07 : Saisie vocale des notes
**Sprint** : 2 **MVP** : Non **Points** : 5

**Description** : En tant qu'utilisateur, je veux dicter une note pour un ami afin d'ajouter de l'information plus rapidement sans avoir à tout taper au clavier.

**Conditions de satisfaction** :
1. L'application demande explicitement la permission d'accès au microphone au système d'exploitation de l'appareil uniquement au moment requis.
2. Les critères sont les mêmes que pour un ajout de note en tapant

### RU-08 : Liaison de fiches amis
**Sprint** : 2 **MVP** : Non **Points** : 8

**Description** : En tant qu'utilisateur, je veux pouvoir lier la fiche d'un ami à un autre compte de l'application afin de mieux représenter les relations entre utilisateurs réels dans le système.

**Conditions de satisfaction** :
1. Le lien ne peut être établi que vers un compte utilisateur existant et requiert son consentement ou le respect d'une politique de visibilité stricte.
2. Cette liaison ne doit en aucun cas donner accès aux notes ou informations privées de la fiche d'un utilisateur à l'autre sans autorisation d'accès explicite.
3. L'association peut être révoquée à tout moment par l'un des deux comptes, coupant immédiatement l'accès aux données partagées ou liées.

### RU-09 : Résumé IA des notes
**Sprint** : 2 **MVP** : Non **Points** : 5

**Description** : En tant qu'utilisateur, je veux voir sur la page d'un ami un court résumé généré par l'IA à partir de mes notes afin de comprendre rapidement les informations importantes qui le concernent.

**Conditions de satisfaction** :
1. Si il y a trop de notes pour le contexte IA, les notes les plus récentes sont utilisées.
2. Seules les notes dont l'utilisateur est le propriétaire légitime peuvent être transmises pour la génération de résumés.
3. Le résultat de l'IA n'est pas stocké en DB, juste affiché dans l'interface

### RU-10 : Génération et partage de message IA
**Sprint** : 2 **MVP** : Non **Points** : 5

**Description** : En tant qu'utilisateur, je veux générer automatiquement avec l'IA un message personnalisé à envoyer à un ami afin de reprendre contact plus facilement, puis le partager avec le menu de partage du téléphone.

**Conditions de satisfaction** :
1. Seul l'utilisateur propriétaire de la fiche de l'ami peut solliciter la génération d'un message et y accéder.
2. L'accès à la fonctionnalité de génération de message est soumis à un contrôle de quota d'utilisation (rate limiting) pour éviter tout abus de ressources de l'IA.
3. Le partage via l'API native n'expose que le message texte final sans aucune métadonnée ou clé d'accès sensible de l'utilisateur ou du système.
